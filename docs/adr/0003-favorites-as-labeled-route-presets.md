# Favorites as labeled route presets with a Deluxe management window

JetBrains favorites stop being flat `(provider, model)` stars and become **route presets**: a named combination of provider + model + OpenRouter route (null = Auto) + reasoning effort (null = Auto), carrying user-assigned **labels**. A preset is stored once and shown in every IntelliJ project whose name matches one of its labels (case-insensitive); **unlabeled presets are visible in no project popup**. Presets live in an **IDE-global store** (application-level `PersistentStateComponent` in the config directory with default roaming) so they survive IntelliJ version updates and Settings Sync — deliberately not `workspace.xml`, and deliberately JetBrains-only: the CLI, `model.json`, and the shared provider-state DTOs stay untouched. The session parameter popup is rebuilt as a **Deluxe-owned clone of the upstream `ModelPicker` popup experience** (search, sections, hover details sidecar) with a Favorites section of visible presets on top and an edit-favorites button on that section's line; the KILO-8.4 route/effort sections leave the popup entirely — presets become the composition unit, composed in a new **non-modal management window** modeled on IntelliJ's Data Sources and Drivers dialog, gated to routing-enabled (OpenRouter-compatible) providers, showing route endpoint data (uptime/pricing/quantization via the CLI `/kilo/routes` proxy) with sort/filter, and model prices with RPG-style green/red deltas against the preset currently selected in the window list.

## Considered Options

- **Extend upstream `ModelPicker`/`PickerPopup` in place** — rejected per ADR-0001: highest-churn upstream files, route/favorites concepts leak into settings surfaces.
- **Keep the KILO-8.4 `KiloParameterPicker` popup and bolt presets onto it** — rejected: the product decision is to return to the old popup experience (models + hover sidecar); its inline route/effort sections retire (they also carry the diagnosed below-the-fold, invisible-Loading, and scroll-yank defects — eliminated by removal, recorded per the design ticket's acceptance criteria).
- **Shared `PickerPopup` shell + a small marked hook for section-header actions** — rejected in favor of cloning the popup chain (shell, list renderer, rows/renderer, details panel) into `ai.kilocode.client.deluxe`: the popup diverges heavily (preset rows, Favorites-line button, sidecar content), and zero upstream churn outweighs the duplicated lines.
- **Replace flat favorites everywhere / import them as presets** — rejected: flat `model.json` favorites stay exactly as they are for the TUI and the upstream pickers (settings, agent edit, New Worktree dialog); the session popup simply stops reading them, and Ctrl+2 cycles visible presets with a flat-favorites fallback.
- **Labels with a managed vocabulary; unlabeled = global** — rejected: free-form tags auto-created as typed; unlabeled presets are visible nowhere, which makes the project-name label the single visibility mechanism.
- **Tabs in the management window (`all | project1 | project2`)** — rejected in favor of an **accordion grouped by label** whose collapsed groups auto-expand under the drag cursor.
- **Global preset ordering** — rejected: ordering is **per label** (each project's popup orders its presets by its label's sequence), with a per-view "order alphabetically" button.
- **Price-delta baseline = session's current model** — rejected: the window is session-independent; the delta compares the hovered preset against the preset currently selected in the window list (inventory style).
- **Modal dialog / tool window / settings page** — rejected: a non-modal `DialogWrapper` with OK/Cancel/Apply that never blocks other IntelliJ windows or popups.

## Consequences

- The store shape is `{id, unique name, labels[], provider, modelId, routeTag?, variant?}` plus per-label order maps; names are unique (auto-suffix on conflict); sanitize on load.
- The star on a catalog model row toggles per-model visibility in the current project: starring creates a preset named after the model with the currently-in-effect route/effort labeled with the project's name; unstarring removes the project label from the model's visible presets ("favorite = route preset"); the preset survives in the management window and is deletable there. The toolbar's duplicate action is the only independent fork.
- Drag gestures: row → group adds that label at the drop position; row within a group reorders that label's sequence. Copy-to-project is label assignment — one underlying preset, edits propagate everywhere; running conversations keep their pinned values (ADR-0002's on-demand re-resolution contract, no new mechanism).
- The lock rule holds: the popup shows an Unlock row while frozen, preset picks are refused while frozen, and a picked preset applies model+route+effort as one through the per-project parameter store.
- Route staleness follows keep-pin: a preset whose route tag or effort variant disappears from the refreshed data is flagged, never auto-cleared.
- The KILO-8.4 route-fetch path moves out of the popup into the management window; the popup performs no route fetching.
- This design is a first cut expected to change after field testing — modification tickets will follow user testing rather than pre-emptive speculation.
